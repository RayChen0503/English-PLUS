# STORE-4 Screenshot and Device Brief

Use the production release candidate and fictional review accounts only. The
screenshots should explain the product in six frames without exposing email,
evidence files, class codes, debug labels, device notifications, or real
student data.

| Order | Screen | Required visible proof | Suggested overlay copy |
| --- | --- | --- | --- |
| 1 | Student daily check-in result | Today's time/state/preferences and a finite generated mission | 今天的狀態，變成做得到的任務 |
| 2 | Submitted wrong answer | Post-submit feedback and AI explanation; no pre-answer answer leak | 答錯不是結束，而是下一步的開始 |
| 3 | Free practice | Type, difficulty, skill group, and reachable finite set | 依題型與程度，自主選擇練習 |
| 4 | Student support thread | Exact question context plus teacher/volunteer reply | AI 即時協助，真人接續回覆 |
| 5 | Teacher class workspace | Fictional roster, assignment state, and progress | 一個班級，掌握任務與學習進度 |
| 6 | Volunteer relay | Approved volunteer, authorized class, scoped pending request | 通過審核後，只服務被授權的班級 |

## Capture rules

- Capture the current iPhone-first UI in both light and dark mode during QA;
  submit one visually coherent mode for the storefront set.
- Use the largest accepted iPhone display set available in App Store Connect;
  provide any additional required device class shown by the upload interface.
- Keep text at the default Dynamic Type size for storefront screenshots, then
  separately verify accessibility sizes on device.
- Do not composite controls that are not present in the app. Marketing copy may
  be added outside the device frame only when it remains truthful.
- Re-capture after any UI or seed-data change. The App Review build and product
  page must describe the same release candidate.
